✦ Orchestration Layer ✧

ported จาก tentacle/terminal/channel model — ปรับให้ใช้ Claude API แทน PTY

▸ Concept Mapping: Repo → ระบบใหม่
Tentacle ADAPTED
Repo: folder .octogent/tentacles/<id>/ พร้อม CONTEXT.md + todo.md

เรา: Task entity ใน PostgreSQL — มี title, context (markdown), todos[], assignedCharacterId
Terminal / Session ADAPTED
Repo: PTY session ที่รัน claude CLI จริงๆ

เรา: AgentSession — conversation กับ Claude API ที่มี characterId, taskId, parentSessionId?
Parent Coordinator PORTED
Character หนึ่งตัวรับ task ใหญ่ → วิเคราะห์ → สั่ง spawn worker sessions สำหรับ character อื่นๆ ผ่าน tool call พิเศษ spawn_worker
Channel Messaging PORTED
ส่ง message ระหว่าง characters — inject เข้า conversation ของ target character เมื่อเป็น idle ในรูป [Message from Mai]: ...
Worker (up to 9) PORTED
Child session ที่ spawn จาก todo item — แต่ละ worker รู้ว่าตัวเองทำ task ไหน, parent คือใคร

▸ Orchestration Flow
1. User สร้าง Task พร้อม context + todos
→
2. User เลือก coordinator character (เช่น Yui)
→
3. Yui วิเคราะห์ todos → ส่ง spawn_worker tool call
4. Nest.js spawn AgentSessions สำหรับ character แต่ละตัว + inject task context
→
5. Workers ทำงานพร้อมกัน สูงสุด 9 ตัว
→
6. Channel messaging ระหว่าง workers เมื่อต้องการ coordinate
▸ Database Schema เพิ่มเติม
TableFieldsหมายเหตุ
Task id, title, context, coordinatorCharacterId, status, createdAt เทียบกับ Tentacle
TodoItem id, taskId, text, status, assignedCharacterId?, workerSessionId? ใน todo.md ของ repo
AgentSession id, characterId, taskId?, parentSessionId?, state, createdAt เทียบกับ Terminal
ChannelMessage id, fromSessionId, toSessionId, content, delivered, createdAt in-memory ใน repo, เราเก็บใน DB
▸ Limits เหมือน repo (ported)
Max 9 workers per coordinator — เหมือน repo ทุกอย่าง
Channel message ส่งได้เฉพาะ idle session เท่านั้น
Character prompt prepend ทุก session — สไตล์ตัวละครอยู่ครบ
